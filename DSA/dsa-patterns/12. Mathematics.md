## 2. Questions to Ask Before Applying Math

1. Can I precompute values (primes, factorials, inverses)?
2. Is the input size large (e.g., compute mod 1e9+7)?
3. Are divisors or co-primes involved?
4. Does the problem ask for “ways”, “combinations”, “arrangements”?

## 4. Code Templates

1. Sieve of Eratosthenes (Primes ≤ N)  

```cpp
vector<bool> isPrime(N+1, true);
isPrime[0] = isPrime[1] = false;
for (int i = 2; i * i <= N; ++i) {
    if (isPrime[i]) {
        for (int j = i * i; j <= N; j += i)
            isPrime[j] = false;
    }
}
```

2. GCD & LCM

```cpp
int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);
}
int lcm(int a, int b) {
    return a / gcd(a, b) * b;
}
```

3. Modular Exponentiation (a^b % mod)

```cpp
long long power(long long a, long long b, long long mod) {
    long long res = 1;
    a %= mod;
    while (b > 0) {
        if (b & 1) res = (res * a) % mod;
        a = (a * a) % mod;
        b >>= 1;
    }
    return res;
}
```

4. Modular Inverse using Fermat’s Little Theorem  
(only when mod is prime)

```cpp
int modInverse(int a, int mod) {
    return power(a, mod - 2, mod);
}
```

5. Modular Arithmetic Toolkit (Add, Subtract, Multiply, Divide)

Use these four instead of hand-rolling `%` logic inline — the subtract case in particular is a common off-by-negative bug.

```cpp
const long long MOD = 1e9 + 7;

long long modAdd(long long a, long long b) { return ((a % MOD) + (b % MOD)) % MOD; }
long long modSub(long long a, long long b) { return ((a % MOD) - (b % MOD) + MOD) % MOD; }
long long modMul(long long a, long long b) { return ((a % MOD) * (b % MOD)) % MOD; }
long long modDiv(long long a, long long b) { return modMul(a, power(b, MOD - 2, MOD)); }
```

- **Add**: mod each operand first, then mod the sum — keeps intermediate values small.
- **Subtract**: C++'s `%` can return a negative result when the left side is negative (`(-3) % 5 == -3` in C++, not 2). Always add `MOD` back before the final `% MOD`.
- **Multiply**: cast to `long long` before multiplying (`1LL * a * b`), or two `int`s near 1e9 overflow before you ever get to reduce mod.
- **Divide**: there's no native "mod division" — `a / b mod m` means `a × modInverse(b) mod m`. The Fermat-based inverse above only works when `m` is prime (`1e9+7` and `998244353` both are) and `b` is not a multiple of `m`. For a non-prime `m`, use the Extended Euclidean Algorithm to find the inverse instead.

6. nCr % mod using precomputed factorials  

```cpp
const int N = 1e6 + 5;
int mod = 1e9 + 7;
vector<long long> fact(N), invFact(N);

void precompute() {
    fact[0] = invFact[0] = 1;
    for (int i = 1; i < N; ++i)
        fact[i] = (fact[i - 1] * i) % mod;
    invFact[N - 1] = modInverse(fact[N - 1], mod);
    for (int i = N - 2; i > 0; --i)
        invFact[i] = (invFact[i + 1] * (i + 1)) % mod;
}

long long nCr(int n, int r) {
    if (r > n || r < 0) return 0;
    return fact[n] * invFact[r] % mod * invFact[n - r] % mod;
}
```

---

## 5. Pro Tips

- Always cast to `1LL ×` for multiplication in C++ to avoid overflow
- For factorial-based problems with mod, always precompute factorials and modular inverses
- For GCD-related constraints, try reducing the problem using GCD
- Use Sieve when answering multiple prime-related queries
- Modular inverse via Fermat only works when the mod is prime. For non-prime mods, use Extended Euclid.
