## Step-By-Step Approach

---

### Recognize It

- Problem says "Design a class that supports these operations" with specific time complexity
- You need to combine two data structures to hit a complexity no single one gives alone
  (e.g. O(1) get + O(1) evict → HashMap + Doubly Linked List)

---

### 1. Master These 5 Core Design Patterns

| Pattern                          | Example Problem               | Key Idea                                              |
| ---------------------------------- | -------------------------------- | -------------------------------------------------------- |
| 1. HashMap + Doubly Linked List   | LRU Cache                      | O(1) lookup via map, O(1) reorder via linked list        |
| 2. HashMap + Frequency Buckets    | LFU Cache                       | Track freq per key, bucket keys by freq for O(1) evict   |
| 3. Two Stacks / Deque             | Min Stack, Design Circular Queue| Auxiliary structure tracks extra state alongside main one|
| 4. HashMap + Array (swap-delete)  | Insert Delete GetRandom O(1)    | Array for O(1) random access, map for O(1) index lookup  |
| 5. Trie / Nested HashMap          | Design File System, Autocomplete| Tree of maps mirrors the nested structure being modeled  |

---

### 2. Questions to Ask Yourself

1. What are the exact required time complexities for each operation? Write them down first.
2. Which single structure gives me most operations for free, and what's still missing?
3. Do I need order (linked list / array) as well as lookup (hashmap)? → combine them
4. Is there a natural recursive/nested shape (paths, hierarchies)? → Trie or nested map

### 3. Must-Know Problems by Pattern

| Problem                                  | Pattern                  | Key Idea                                         |
| ------------------------------------------ | --------------------------- | --------------------------------------------------- |
| 1. LRU Cache                              | HashMap + DLL             | Move node to front on access, evict tail on overflow |

| 3. Min Stack                              | Two Stacks                | Second stack tracks running minimum                 |
| 4. Insert Delete GetRandom O(1)           | HashMap + Array            | Swap target with last element before popping        |

### 4. Code Templates You Must Know

1. LRU Cache (HashMap + Doubly Linked List)

```cpp
class LRUCache {
    struct Node { int key, val; Node *prev, *next; };
    int capacity;
    unordered_map<int, Node*> cache;
    Node *head, *tail; // head->next = most recent, tail->prev = least recent

    void remove(Node* n) { n->prev->next = n->next; n->next->prev = n->prev; }
    void insertFront(Node* n) {
        n->next = head->next; n->prev = head;
        head->next->prev = n; head->next = n;
    }

public:
    LRUCache(int cap) : capacity(cap) {
        head = new Node{0, 0, nullptr, nullptr};
        tail = new Node{0, 0, nullptr, nullptr};
        head->next = tail; tail->prev = head;
    }

    int get(int key) {
        if (!cache.count(key)) return -1;
        Node* n = cache[key];
        remove(n); insertFront(n);
        return n->val;
    }

    void put(int key, int value) {
        if (cache.count(key)) { remove(cache[key]); }
        Node* n = new Node{key, value, nullptr, nullptr};
        cache[key] = n;
        insertFront(n);
        if (cache.size() > capacity) {
            Node* lru = tail->prev;
            remove(lru);
            cache.erase(lru->key);
        }
    }
};
```

2. Min Stack (Two Stacks)

```cpp
class MinStack {
    stack<int> st, minSt;
public:
    void push(int val) {
        st.push(val);
        minSt.push(minSt.empty() ? val : min(val, minSt.top()));
    }
    void pop() { st.pop(); minSt.pop(); }
    int top() { return st.top(); }
    int getMin() { return minSt.top(); }
};
```

3. Insert Delete GetRandom O(1)

```cpp
class RandomizedSet {
    vector<int> data;
    unordered_map<int, int> index; // value -> position in data

public:
    bool insert(int val) {
        if (index.count(val)) return false;
        index[val] = data.size();
        data.push_back(val);
        return true;
    }
    bool remove(int val) {
        if (!index.count(val)) return false;
        int idx = index[val], last = data.back();
        data[idx] = last;
        index[last] = idx;
        data.pop_back();
        index.erase(val);
        return true;
    }
    int getRandom() { return data[rand() % data.size()]; }
};
```

4. Design Circular Queue

```cpp
class MyCircularQueue {
    vector<int> buf;
    int head = 0, count = 0, capacity;
public:
    MyCircularQueue(int k) : buf(k), capacity(k) {}
    bool enQueue(int val) {
        if (count == capacity) return false;
        buf[(head + count) % capacity] = val;
        count++;
        return true;
    }
    bool deQueue() {
        if (count == 0) return false;
        head = (head + 1) % capacity;
        count--;
        return true;
    }
    int Front() { return count == 0 ? -1 : buf[head]; }
    int Rear() { return count == 0 ? -1 : buf[(head + count - 1) % capacity]; }
};
```

### 5. Tips for Success

- Write the required time complexity for every operation before picking a structure
- LRU/LFU are the two most-asked design problems — know the DLL trick cold
- When two structures need to stay in sync (map + list, map + array), update both in every method
- Don't reach for a database-style solution — interviewers want the minimal composition of structures
- Test eviction/edge cases: empty structure, capacity of 1, duplicate inserts
