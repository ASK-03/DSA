## Step-By-Step Approach

---

### Recognize It

- Interviewer asks you to implement a sort from scratch, not just call `sort()`
- Problem needs partial order (Kth largest, top K) → don't fully sort, use quickselect/heap
- Input has a tiny value range (0/1/2, or 0-255) → counting sort beats comparison sort

---

### 1. Master These 6 Core Sorting Algorithms

| Algorithm       | Time (avg/worst) | Space    | Key Idea                                          |
| --------------- | ----------------- | -------- | -------------------------------------------------- |
| 1. Merge Sort   | O(n log n) / O(n log n) | O(n)     | Divide, sort halves, merge — stable                |
| 2. Quick Sort   | O(n log n) / O(n²)      | O(log n) | Partition around pivot, recurse on both sides      |
| 3. Heap Sort    | O(n log n) / O(n log n) | O(1)     | Build max-heap, repeatedly extract max             |
| 4. Counting Sort| O(n + k) / O(n + k)     | O(k)     | Bucket by value when range k is small              |
| 5. Quickselect  | O(n) / O(n²)            | O(1)     | Partition like quicksort, recurse one side only    |
| 6. Insertion Sort | O(n²) / O(n²)         | O(1)     | Good for nearly-sorted or tiny inputs              |

---

### 2. Questions to Ask Yourself

1. Do I actually need a full sort, or just the top/bottom K? → Quickselect or heap
2. Is the value range small and known? → Counting sort beats O(n log n)
3. Does stability matter (equal elements keep relative order)? → Merge sort, not quicksort
4. Is extra O(n) space acceptable? If not, prefer heap sort or in-place quicksort

### 3. Must-Know Problems by Pattern

| Problem                              | Pattern            | Key Idea                                    |
| -------------------------------------- | ------------------- | -------------------------------------------- |
| 1. Sort an Array                      | Merge / Quick Sort  | Implement a comparison sort from scratch      |
| 2. Kth Largest Element in an Array    | Quickselect         | Partition until pivot lands at index `n-k`   |

### 4. Code Templates You Must Know

1. Merge Sort

```cpp
void mergeSort(vector<int>& a, int l, int r) {
    if (l >= r) return;
    int m = (l + r) / 2;
    mergeSort(a, l, m);
    mergeSort(a, m + 1, r);
    vector<int> tmp;
    int i = l, j = m + 1;
    while (i <= m && j <= r) tmp.push_back(a[i] <= a[j] ? a[i++] : a[j++]);
    while (i <= m) tmp.push_back(a[i++]);
    while (j <= r) tmp.push_back(a[j++]);
    copy(tmp.begin(), tmp.end(), a.begin() + l);
}
```

2. Quick Sort (Lomuto Partition)

```cpp
int partition(vector<int>& a, int l, int r) {
    int pivot = a[r], i = l;
    for (int j = l; j < r; ++j)
        if (a[j] < pivot) swap(a[i++], a[j]);
    swap(a[i], a[r]);
    return i;
}
void quickSort(vector<int>& a, int l, int r) {
    if (l >= r) return;
    int p = partition(a, l, r);
    quickSort(a, l, p - 1);
    quickSort(a, p + 1, r);
}
```

3. Quickselect (Kth Largest)

```cpp
int quickSelect(vector<int>& a, int l, int r, int k) { // k = target index (0-based, ascending)
    int p = partition(a, l, r);
    if (p == k) return a[p];
    return p < k ? quickSelect(a, p + 1, r, k) : quickSelect(a, l, p - 1, k);
}
int findKthLargest(vector<int>& nums, int k) {
    return quickSelect(nums, 0, nums.size() - 1, nums.size() - k);
}
```

4. Counting Sort (Sort Colors)

```cpp
void sortColors(vector<int>& nums) {
    int count[3] = {0, 0, 0};
    for (int n : nums) count[n]++;
    int idx = 0;
    for (int c = 0; c < 3; ++c)
        while (count[c]--) nums[idx++] = c;
}
```

5. Heap Sort (via priority_queue)

```cpp
vector<int> heapSort(vector<int> a) {
    priority_queue<int, vector<int>, greater<int>> pq(a.begin(), a.end());
    vector<int> res;
    while (!pq.empty()) { res.push_back(pq.top()); pq.pop(); }
    return res;
}
```

---

### 5. Tips for Success

- `sort()` in interviews is fine unless asked to implement one — know merge/quick/heap sort cold when asked
- Quickselect gives O(n) average for "Kth largest/smallest" — don't over-sort
- Counting sort only works when the value range is small and known ahead of time
- Merge sort is the go-to when you need stability or are sorting a linked list
- Custom comparators (e.g. Largest Number) are a common interview twist — practice writing them
